# Planazo redesign — handoff notes

_Last updated 2026-07-28, after PR #6 (create sheet 5a) merged. Next phase: groups suite._

**Architecture (settled, do not relitigate):** React Native/Expo (SDK 54), Supabase-only backend (RLS + SECURITY DEFINER RPCs; Edge Functions later for push/AI; no Express — deleted in Phase 0 after explicit discussion). User-facing word is **"Groups"** (never "Circles"); profile is the **12b/14a menu-style sheet** (read-only, Edit button, Send-feedback row). The user is sensitive to unflagged structural changes AND to deviations from the design doc — if implementing less/differently than the design shows, say so explicitly first.

**Product decisions made in Phase 4 (apply everywhere):**
- **Host counts from creation**: posting a fixed plan auto-inserts the creator's yes-RSVP; posting a flexible plan auto-inserts their availability on every proposed day. An 11-person plan opens at "10 more".
- **Cap ≥ min** (diverges from the design script's cap > min, user-requested): cap-up from "No limit" lands on min itself; a climbing min drags the cap along to match; exact headcount (min == cap) is valid.
- **Dates render en-GB** ("Fri 31 Jul", "Friday 31 July") app-wide; the design mocks are en-US.
- **HARD RULE — never string-parse dates on Hermes.** `new Date('YYYY-MM-DD')` is UTC midnight (stored flexible options a day early on negative UTC offsets) and `new Date('…T20:30:00')` disagrees with the native picker's offset (wheel showed 19:30 for a 20:30 pill). Always build via `new Date(y, m-1, d, h, min)`. Both bugs shipped and were fixed in PR #6 — don't reintroduce.
- Known data caveat: flexible plans seeded **before** PR #6 still carry UTC-midnight option dates and may display a day early on negative-offset timezones; new plans are correct.
