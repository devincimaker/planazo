User-facing word is **"Groups"**, never "Circles". Style ONLY from `theme/tokens.ts` + `components/ui` (no raw hex in screens; numeric paddings from design markup are fine). ## Last phase: Endgame (in likely order)

1. **Push notifications** — the only genuinely new machinery.
   - `expo-notifications` (native → rebuild), register the Expo push token on sign-in into `profiles.push_token` (column exists).
   - The `notifications` table already exists (`user_id, type, title, body, data jsonb, read`; type ∈ `plan_created / plan_locked / plan_cancelled / invited_to_group / kicked_from_group`; select/update-own RLS) and the lock/cancel/reopen RPCs **already insert rows** (`20260728000000` and `…000002`). Nothing writes `plan_created` yet — add that on plan insert, honoring `group_members.notify_new_plans` (toggle already live in Manage).
   - Delivery: an **Edge Function** (would be the repo's first — no `supabase/functions/` yet) that sends rows via Expo's push API. Trigger mechanism (DB webhook on insert vs. pg_net trigger vs. poll) is undecided — propose one to the user before building.
   - **12b's "Notify me" global toggle** was deliberately left out of the profile sheet in phase 6 because it had nothing to control. When push lands, add it back (needs a `profiles` column) — design anchor: profile sheet section of the design file, `renderVals()` holds the toggle state.
2. **Cancelled/expired plan states** — cancelled plans (`plans.status='cancelled'`) are currently just filtered out of feed/group lists; surface them properly, and decide what happens to open plans whose date has passed (expire vs. badge). **No designed target exists — agree the behavior with the user first.**
3. **Integration test suite** against local Supabase in CI — real RLS/RPC coverage. (Motivating bugs: mocked tests couldn't see that pending invitees were RLS-blocked from reading a group's name; only on-device passes caught that and two date bugs.)
4. **Small carry-over:** the OS-screenshot feedback entry (phase 6) is fully verified downstream, but the iOS screenshot notification **cannot fire in the Simulator** (host-side capture) — ask the user to take one screenshot with the app open on their physical phone to confirm the listener hop.
