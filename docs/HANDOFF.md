## Last phase: Endgame (in likely order)

1. **Push notifications — BUILT on `phase-8-push`** (migration `20260730000001`, pushed to live DB and verified there).
   - Architecture: notification INSERT → `trg_push_notification` (pg_net) POSTs `{id}` to the `send-push` Edge Function → Expo push API. The function claims the row by stamping `notifications.pushed_at` first (idempotent), reads `profiles.push_token`/`push_enabled`, and clears dead tokens on `DeviceNotRegistered`. Auth: the app's `sb_publishable_…` key is not a JWT, so the function runs with `verify_jwt = false` (config.toml) and requires an `x-push-secret` header — the secret lives in Vault (`send_push_secret`, seeded on live) for the trigger, in root `.env` as `PUSH_TRIGGER_SECRET` for deploys. Webhook failures never break the insert.
   - `plan_created` fan-out: `trg_notify_plan_created` on plans notifies members with `notify_new_plans` on, excluding the creator. Copy: fixed `X put up "T" — are you in?`, flexible `… — pick the dates that work.` Live-verified (7-member group, 1 muted → 5 rows, 5 pg_net POSTs).
   - App: `lib/push.ts` registers the token after sign-in (device-only, once per run, permission-gated); sign-out clears it. 12b "Notify me" toggle is in the profile sheet (`profiles.push_enabled` — gates delivery only, feed rows unaffected). Tapping a push routes to `data.plan_id`, cold start included (`_layout.tsx` holds the id until nav+auth are ready).
   - **USER-BLOCKED — deploy**: needs a Supabase access token (CLI login broken on this machine). Then: `supabase functions deploy send-push --project-ref lmgjdvacivzzhctgctqa` and `supabase secrets set PUSH_TRIGGER_SECRET=<root .env value> --project-ref …`. Until deployed, pg_net POSTs 404 harmlessly; rows keep `pushed_at NULL`.
   - **USER-BLOCKED — APNs**: real-device delivery also needs APNs credentials on the EAS project (`eas credentials -p ios`) and a dev build on the physical phone. Simulators can't receive remote pushes at all.
2. **Cancelled/expired plan states — DONE on `phase-7-endings`** (design: `Planazo Endings.dc.html`). Settled semantics: expiry is computed at read time (no background job) — a plan is past at local midnight after its last possible day (`isPlanPast` in shared); past+under-min = "Didn't happen", past+reached-min = happened (nothing changes on detail for MVP). `cancel_plan(p_plan_id, p_reason)` stamps cancelled_at/by/reason; `restore_plan` un-cancels while the date is ahead and notifies `plan_reopened` (new type in the CHECK). Feed notice (19e) is driven by the unread `plan_cancelled` row (<24h); "Got it" marks it read. Deliberate deviations, flagged to user: 20a's "Edit the details" row deferred (no designed plan-edit screen — tasks.md); host-menu semantics use the app's existing isHost (creator OR group admin), so admins also see Call it off / Reopen.
3. **Integration test suite** against local Supabase in CI — real RLS/RPC coverage. (Motivating bugs: mocked tests couldn't see that pending invitees were RLS-blocked from reading a group's name; only on-device passes caught that and two date bugs.)
